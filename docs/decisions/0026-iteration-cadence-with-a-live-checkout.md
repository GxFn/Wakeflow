# ADR-0026 迭代节奏：开发检出直接作为插件来源时的部署、版本、tag 与现场

> 状态：`accepted`
> 提出日期：2026-11-08
> 裁决日期：2026-11-08（用户委托起草者确定）
> 基线提交：`ecdd20fb`
> 相关：ADR-0021（发布模型与平台范围）、ADR-0025（双传输）、双传输规划 §3、gate-log §13.230、open-items Q2

## 背景

- 用户于 2026-11-08 建立正式工作区（根仓库加五个核心产品仓库的克隆，桌面传输），并裁定保持"便捷开发"的状态：Claude Code 的目录型 marketplace 指向本检出，插件直接从 `plugins/claude-code-wakeflow` 加载，不另设发布克隆；提交与推送由用户把控，用户监督 Wakeflow 的使用情况。
- 因此每次 `npm run build:artifacts:committed` 都是一次部署：新会话立刻加载新字节，正在运行的服务进程报 `runtime-artifact-outdated`，桌面窗口变为 `windows-refresh-pending`，助手字节变化时工作区欠一次 reconcile（§13.226 起多次现场所见）。
- ADR-0021 定了版本模型——停用 rc、一版本一字节、tag 打在 bump 提交上、tag 后真跑 `release:check`——没有定迭代节奏。`v1.2.0` 于本日打在 `ecdd20fb`，`release:check` 通过（§13.230）。
- 仓库里曾留下一条由派生会话创建的分支与其 `.claude/worktrees/` 工作树，没有独有提交，本日删除。

## 问题

开发检出同时是正式工作区的插件来源时，什么时候重建制品、什么时候 bump 与 tag、每个 tag 前做多少现场，需要一条可执行的节奏；没有它，半成品字节会在任意时刻进入正式工作区。

## 决定

1. **主干开发。** 只在 `main` 上开发。派生会话的分支与 `.claude/worktrees/` 下的工作树在合并或放弃后即删除，不保留长期分支。
2. **阶段即部署。** 一个阶段（若干批次）以一道完整门收口并提交，`plugins/` 只在阶段末重建一次。重建前先确认正式工作区没有活动 Demand——以其 Controller 的状态卡为准，维护者不向该工作区写入任何东西——重建后在交接里说明；该工作区的 Controller 在下一次 `/wakeflow:next` 走"插件更新后"的路径（reconcile、窗口换代）。阶段中途的试验只在一次性测试工作区做。
3. **版本号。** `v1.2.0` 之后，任何改变 `plugins/` 字节的阶段先 bump 补丁号（ADR-0021 规则 2，`wf handoff` 的 `version-bytes` 检查强制）；新增公共工具、画像字段、传输能力或 Schema 的批次推进小版本；持久格式（状态、历史、Schema）的不兼容变化才推进大版本。
4. **tag 与发布检查。** 每个阶段的 bump 提交推送后打轻量 tag，紧接着真跑一次 `release:check`；tag 与推送由用户执行或明确授权，维护者不自行推送。
5. **现场分级。** 小版本 tag 前两种传输各走一遍窗口生命周期现场（规划 §3）；补丁 tag 前只对改动触及的传输做现场，改动不触及助手、启动指令、观察或投递文本时可以只凭门与 smoke 出 tag。正式工作区是桌面传输的受监督现场：在那里发现的问题先登记到 open-items 再修，不在那里做试验、不发测试用的需求包。
6. **节奏单位。** 以"一个阶段、一道门、一次部署"为单位，不按日历；一天内多个阶段时只在最后一个阶段末重建与 tag。

## 后果

- CLAUDE.md 与 AGENTS.md 的 Scope And Safety 加一条规则：正式工作区直接加载本检出的制品，重建即部署。
- 双传输规划 §3 的"每次 tag 前两传输各回归一次"改为按小版本与补丁分级。
- open-items 的 Q1、Q2、Q11 按 ADR-0021 标为已裁决，Q2 的节奏指向本文。
- 下一次改动 `plugins/` 字节之前，先 `npm run wf -- release bump --version 1.2.1 --apply`。

## 未决问题

- 用户不在场时正式工作区的 Controller 收到"制品过期"怎么办：现在是等用户的下一次 `/wakeflow:next`。
- 是否值得给维护者一条只读的"正式工作区是否空闲"命令，而不是每次手写 `wf mcp call`。
