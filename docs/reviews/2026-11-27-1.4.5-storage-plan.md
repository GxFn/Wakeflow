## 0. 结论

量过之后，C 能删的东西有个明确的上限，而且大头不在原先设想的地方。foundation 以上直接碰存储的 97 个模块共 59,321 行，其中与存储有关的样板是 3,449 行（5.8%）：**把底层错误翻成自己的原因 2,823 行，自己核对节点 626 行。** 读、写、删这些调用本身没有多少可省：三个试点候选换成端口动词，各自只少 4% 到 12%。

所以建议不按"一个存储一个存储换端口"做，而是**按样板的形状一批一批删**：每一批是一条规则，机械、可验证，哪一批不划算就停在那里。

## 1. 量出来的事实

| 项 | 数 |
|---|---|
| 直接调存储原语或自己核对节点的模块 | 97 个，59,321 行（11 月 19 日是 98 个） |
| 错误翻译 | 2,823 行，90 个模块；318 处 `catch` 加 15 个具名函数 |
| 节点策略（属主、权限位、链接数） | 626 行，48 个模块；其中 50 个具名函数 495 行 |
| 读 / 列目录 / 独占新建 / 比较后替换 / 删除 | 75 / 39 / 32 / 20 / 22 处 |
| 只问"在不在"的探测 | 65 处，另有 27 个"不存在就返回 null"的包装函数 |
| 自己调暂存恢复 | 17 个模块（12 个直接调原语） |
| 自己组合锁 | 0（ADR-0033 之后都走锁名表） |

错误翻译里反复出现的形状（行数 / 文件数）：中止翻成中止 280 / 86（按 `reason === "aborted"` 数是 356 行）；不存在翻成 null 103 / 61；其余一律翻成"前缀加原因"的 io 失败 106 / 28；提交不确定一族 30 / 19；目标已在翻成冲突 26 / 21；预期已变翻成冲突 23 / 20。

## 2. 做法：五批，每批一条规则

1. **中止只有一种错误，只在边界翻一次。** 今天 32 个原语各自带一个 `aborted` 原因，上面每一层再各翻一遍。改成全工程一个中止错误，所有 `catch` 自然放行，命令的边界翻成今天同样的 `io-failure` / `aborted` / `$signal`。**对外一个字节不变。** 预计净减 500 行上下（估计）。
2. **"不存在"是返回值，不是异常。** 读、列目录、探测各给一个"不存在即 null"的入口，27 个包装函数与六十来处翻译随之删掉。对外不变。
3. **私有节点的策略只有一处判断。** 0600 / 0700、属主是当前用户、单链接，由读写入口自己核对；50 个具名函数删掉。对外不变。
4. **通用的 io 失败不再逐模块起名。** 今天 28 个文件把"其余情况"翻成 `<前缀>-<原因>`。改成由边界按原语自己的原因报出。**这一批会改掉一批拒绝原因的名字**（错误码与可否重试不变），开工前单列清单请用户定。
5. **试点一个存储换成端口的写入动词**（维护意图存储：615 行，估计少 70 到 85 行，调用方不用改），量了再定要不要铺开到别的存储。

每一批：Opus 子代理做机械改动，我定规则、看差异；已有测试原样通过（只有断言错误类型的地方跟着改）；每批跑第 0 档，全部做完过一次门。

## 3. 不动的

- `RootedDirectory` 仍是各层的参数类型（129 个模块在用，198 个测试文件靠它切换落盘级别）；入口都从它构造。
- 目录树候选的整套生命周期、根之外的绝对路径、逐次 `durability: "none"` 的十处，留在原语上。
- 崩溃之后的行为不重新定义：各存储的恢复路径与 1.4.4 相同。

## 4. 预期与上限

批 1 到 3 合计估计净减 1,200 到 1,600 行；五批做完的上限是第 0 节那 3,449 行，到不了。对比：D 一个原语净减 1,340 行。C 的收益主要是"以后改存储只改一处"，行数是其次。

## 5. 需要用户定的

1. 按形状分批删，而不是逐个存储换端口——同意吗。
2. 批 4 的拒绝原因改名，到时单独给清单。
3. 批 5 之后要不要铺开，看试点的数字再定。
