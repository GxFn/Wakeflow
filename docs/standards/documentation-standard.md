# Wakeflow 文档编写标准

> 状态：`active`
> 建立日期：2026-09-03
> 上位文档：[docs/README.md](../README.md)

本标准规定开发文档系统内每份文档的头部、语言、证据、链接和归档写法。它只约束 `docs/` 目录；插件内的 README、指令文件和 skills 由各自的验证器约束。

## 1. 头部

正文第一行是一级标题。标题之后用引用块写状态区，每行一个字段，字段名后接中文冒号：

```markdown
# 文档标题

> 状态：`active`
> 基线提交：`c0098e2`
> 建立日期：2026-09-03
> 上位文档：[docs/plan/typescript-reimplementation-plan.md](../plan/typescript-reimplementation-plan.md)
```

- `状态` 必填，取值见 [docs/README.md §4](../README.md#4-状态词汇)。
- `基线提交` 在文档陈述代码事实时必填，用短哈希。
- `上位文档` 指向本文档服从的更高权威。
- 从旧位置迁入的文档在状态区加 `原路径`，保留可追溯性。
- 决策记录的头部字段见 [decisions/0000-template.md](../decisions/0000-template.md)。

## 2. 语言

- 正文使用中文。代码标识符、文件路径、工具名、Schema `$id`、错误码、命令原样保留英文并用反引号包裹。
- 术语第一次出现时给出英文原词，之后统一使用同一中文译名。同一概念不得在同一文档内混用多个名字。
- 不使用破折号连接句子；一句话表达一个意思。

## 3. 证据

- 每个数字都要能回答"怎么量的、在哪个提交上量的"。度量方式写在同一段或表格脚注里。
- 引用代码时给出 `路径:行号` 或 `路径` 加符号名，行号会漂移，所以同时给出符号名。
- 引用外部标准或文章时给出可访问的链接，并说明它支持的具体结论。
- 未运行的验证要写明"未运行"，不得由脚本输出、子代理报告或文档叙述冒充通过。
- 不在文档里声称未实现的能力。计划中的能力写"计划"，有 blocker 的写 blocker 名称。

## 4. 结构

- 用 `##` 分节并从 1 编号；`###` 用于子节。编号只在内容确有顺序或需要被引用时使用。
- 并列事项用列表，每项一到两句。步骤用有序列表。对比用表格，表头写明单位。
- 长文档在开头给出"当前结论在第几节"的导读，历史节保留但标注为历史证据。
- 一份文档只服务一个职责。计划不记录进度细节，进度不做决策，评估不改约束。

## 5. 链接

- 文档之间使用相对路径链接，例如 `../plan/typescript-reimplementation-plan.md`。
- 正文提到仓库内其他文件时使用仓库根相对路径，例如 `docs/progress/consolidation-gate-log.md`、`src/foundation/filesystem/rooted-directory.ts`。
- 文档移动时同步更新所有指向它的链接，包括根 README、skills 引用和图谱子项目的刷新触发器。

## 6. 归档

- 完成使命或被取代的文档移入 `docs/archive/`，保留原文件名，不改正文。
- 在 `docs/archive/README.md` 登记：文件、原始日期、类型、状态、被谁取代、是否仍被现行文档引用。
- 仍被引用为需求锚点的归档文档，在 `docs/requirements/README.md` 中列出，说明引用它的现行文档。

## 7. 检查清单

提交文档变更前逐项核对：

1. 头部状态区完整，状态值在词汇表内。
2. 所有相对链接可解析。
3. 数字有度量方式与基线提交。
4. 没有未实现能力被写成已有能力。
5. 没有机器专有路径、令牌、私有会话标识。
6. `git diff --check` 通过。
