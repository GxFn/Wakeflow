# ADR-0015 hook 历史容量与读取完整性

> 状态：`accepted`
> 日期：2026-10-02
> 相关：[修复设计 §3.5、§4.3](../reviews/2026-10-02-reliability-and-contract-repair-design.md)、ADR-0009、ADR-0014

用户确认继续实施既有深审方案后，本批落实 hook 容量修复及缺失制品身份的诊断；没有改变需求事件、配置版本或宿主信任边界。

## 决定

- 保持记录 schemaVersion 1、确定性 recordId 和原文件字节。新文件位于私有 hooks 根的 `YYYYMMDD/<recordId 前两位>/`；读取器同时支持旧平铺文件。旧事实的幂等重试原位返回，不自动迁移，不生成第二份权威；早期缺省 artifactManifestDigest 的合法 v1 字节按有效字段比较，不误判为冲突。
- Foundation 增加稳定目录分页：两次流式枚举各只保留一页加一个前瞻，复验页内节点和目录身份；连续页钉住首个目录快照，变更报错。没有提高旧整目录读取的上限，其他领域仍用原 API。
- Kernel 以固定页面和最多八条记录并发读取；同批文件复用经过双向身份复验的父目录作用域，保留 no-follow 与文件快照检查，减少重复祖先路径校验。全量扫描的聚合只在成功后有效。有限列表新增内部 complete 标志；投递、评审及端点消费者拒绝把不完整列表或存在 skipped 的查询当成完整证据。投递已有独立宿主成功回执或有效 Controller 显式裁决时，继续由既有决定函数判断；hook 列表不完整不能否定这些独立依据，取消与其他 I/O 失败仍传播。status 按会话流式聚合，记录总数与查询数组容量脱钩；会话聚合本身仍有明确上限，超过时 unavailable。
- 新记录写入的原子暂存清点只涉及自己的分片。未知旧条目保留并计入 skipped，不会阻断全部新记录；分片内未知暂存仍保护该分片，不自动覆盖或删除，限定目标的公共恢复仍待实现。
- 清理每次最多检查 4096 个叶条目，只精确删除超过 30 天的已知位置普通记录及足够旧、owner 已失活的已知暂存。截止基准不超过新记录与另一条已观察记录时间的较小者。预算或并发变化可让旧记录保留更久，不能让保留期内的证据因数量被删除；没有新增活动引用自动留存承诺。
- 运行服务曾读取到 manifest、现在同路径不可读时，verify 不再 pass；报告 manifest-unavailable，status/verify 的 next 均交用户检查安装。磁盘缺失与内容变化是不同事实。当前没有宿主选择目标的可靠输入，因此不能声称解决了兄弟版本目录的升级识别。

## 验证边界

覆盖超过旧阈值的合成有效历史、旧平铺重试、按记录 ID 精确取证、结果截断防误判、损坏条目保留、分页变更、取消、两个宿主的观察入口和制品冒烟。大目录合成测试不是长期真实宿主使用的替代；真实进程和公开 MCP 的测量另记 gate-log §13.142。
