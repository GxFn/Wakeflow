# ADR-0007 架构重建授权、职责边界与自底向上开发流程

> 状态：`accepted`
> 提出日期：2026-09-03
> 裁决日期：2026-09-03，用户确认四项
> 基线提交：`c0098e2`
> 相关：[ADR-0003 修订](./0003-host-effect-layer-ownership.md)、[plan §8.1](../plan/typescript-reimplementation-plan.md)、[plan §11 与 §12](../plan/typescript-reimplementation-plan.md)

## 背景

2026-09-03 节点评估之后，用户在进入 P0 前给出了工作方式和职责边界的说明：实施者拥有架构重建的设计权；宿主操作由 Agent 执行而 Wakeflow 负责内容与验证；开发自底向上；债务允许删除重写；测试始终轻量。这些说明影响 ADR-0003 的接受内容和 §8.1 的执行顺序，因此单独建档。

## 决定

### 1. 设计权与确认边界

实施者拥有架构重建的设计权，可以直接做出实现层面的判断。以下情形必须由用户确认后才能执行：

- 存在两个以上可行方案且后果不同；
- 改变已接受的 ADR、TSD 约束、公共合同形状、层边界，或删除旧能力；
- 任何提交、推送、发布、插件缓存刷新。

### 2. Agent 与 Wakeflow 的职责边界

- Agent 执行宿主写效果：开线程、线程投递、开 worktree、创建窗口等。
- Wakeflow 保证内容提供与准确性验证：精确的信封、prompt、任务包；每宿主的动作说明；Agent 交回证据的准入；摘要与状态转换的验证。
- 只读观察由 Agent 观察并交回证据；Wakeflow 不建进程或 PTY 端口，不重建执行型宿主 CLI。
- keep-live 与 unattended 的代码后台自动化先放弃，业务场景层再议。

Codex 与 Claude Code 的差异必须从旧 JS 的对应实现中提炼，落在内容形状、证据形状、指令文件与 skills 文本三处。

### 3. 自底向上的开发流程

- 先更新文档设计，再写代码。
- 顺序固定为：底层基础能力做实，向上功能垂类切片，向上业务场景与联合，最后制品切换。对应 plan §8.1 的 P0 与 L0 到 L3。
- 每层有可度量的退出门；不满足退出门不进入上一层。

### 4. 债务处理

- 债务代码与文件允许删除重写，不要求保留过渡层或 wrapper。
- 守门规则：替代实现的测试通过且对照场景通过后，在同一提交内删除被替代物。
- 跨层或跨 owner 的删除先写 ADR。

### 5. 测试轻量

- 共享一个 v3 基线 fixture 按需复制，替代各自建工作区的 fixture。
- 单元测试用内存值不落盘；每个场景只保留一条端到端链。
- 发现重复证据即删除；治理测试墙钟目标低于 3 分钟。

## 后果

- ADR-0003 的接受内容从选项 A 修订为选项 D；TSD-12 改写。
- plan §8.1 从 P0 到 P5 改为 P0 加 L0 到 L3，并增加"允许删除重写的对象"列。
- plan §11 增加测试轻量规则，§12 增加债务删除守门与设计权确认边界。
- P0 的首要交付物是按能力逐项分析旧 JS 实现并与用户确认后的能力卡，位于 `docs/requirements/capabilities/`，以及能力映射矩阵 `docs/references/capability-map.md`。
