# ADR-0016 窗口投影的发布边界

> 状态：`accepted`
> 日期：2026-10-02
> 相关：[已确认修复设计 §3.2](../reviews/2026-10-02-reliability-and-contract-repair-design.md)、ADR-0014、open-items B6

用户确认继续实施深审修复。本记录落实既有设计中“窗口投影读取、渲染、发布共用 binding-store 锁”的局部边界；不新增工作区全局锁或业务状态机。

## 决定

- Binding 是权威，窗口投影是派生物。端点 register、replace、decommission 已在宿主专用 binding-store 锁内更新绑定及投影；pod 后续刷新与 reconcile 逐窗口操作现在使用同一把锁，从锁内取得 inventory 后渲染并发布。
- 抽出纯渲染函数，零写观察与持锁发布共用。status、verify 和维护 preview 不取得写锁、不恢复暂存、不修改投影，仍按原有完整 inventory 观察规则报告事实。
- 不再把“输出文件 CAS 成功”等同于“渲染依据没有变化”。维护操作在锁内重新核对目标摘要；注册已改变目标时，旧计划被拒绝。刷新遇到无法取得的绑定 inventory 不写，保留现有不可用结果；底层活动锁拒绝、超时、取消和失活恢复规则保持。
- 运行时目录补齐只创建缺失的未登记投影。观察缺失后若另一写入者已发布文件，no-replace 创建冲突只跳过该项，不重新读取后把新文件视为过期并替换。文件不安全仍由既有观察门报告。
- 不在绑定锁内等待 Agent 或宿主效果，也不引入新的持久字段、事件、摘要算法、Schema 或配置策略。

## 锁序与剩余范围

普通端点操作取得既有绑定锁；维护事务可以在其维护 gate 内取得绑定锁；pod 配置提交后的投影刷新也只取得绑定锁。本补丁不引入从绑定锁反向获取维护 gate 或 pod 锁的调用。

本边界保护绑定 inventory 与投影发布，不给传入的 config 快照增加全局排他保证。配置变更、维护事务、其他运行时资源之间的完整并发模型仍属于 B6 的剩余范围，不能将该登记整项关闭。

§13.145 已进一步复现旧配置覆盖新窗口投影，以及活动投影的同类回退；系统性方案见 [ADR-0017 提案](./0017-operation-scope-and-runtime-evidence.md)。该提案尚未替代本记录或现有运行合同。

## 验证

两个宿主各覆盖 refresh、execute、skeleton 三条路径。测试在读到缺失投影后暂停维护，让真实文件系统上的注册及投影发布交错进入，再检查最终字节及下一次 reconcile 是否零操作。旧实现六条路径均可覆盖新登记投影；修复后注册与刷新由既有锁排斥，目录补齐保留竞争胜者。它们是确定性交错文件系统回归，不冒称登录态宿主并发测试。整门和制品结果记录于 gate-log §13.144。
