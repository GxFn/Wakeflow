# 隐私准入与并发观察边界复验

> 日期：2026-10-03
> 状态：active，按用户的继续深入审查与修复要求实施
> 基线：`d8fafff` 上的未提交工作树；延续 ADR-0017、ADR-0018、ADR-0019，不新增本地格式迁移或授权状态机。

## 已复现的原因

1. 隐私引擎把路径识别和原始字符串前缀比较绑定在一起。ASCII 边界误把中文斜杠列表拆出“绝对路径”，路径字符集把正则转义当文件名，原始前缀白名单又允许 `..` 逃出已允许根。盘符、UNC、文件 URI 及冒号后的路径没有统一解释。
2. 凭证赋值只识别裸关键字，未覆盖变量名前缀、JSON 键的闭引号、授权头和连接串用户信息。
3. 证据捕获把带控制字符的有效 UTF-8 判为 opaque 后直接跳过扫描。调用方选择 controller-confirmed 时，连可读的凭证都可能未经过检测。
4. 回调只压平换行，目标撰写的摘要仍以普通文字进入 Controller 的用户轮次。末尾的“无授权”说明不能清楚区分数据和指令；技能还把只读 inspect 描述为确认回调，超出了实际副作用。
5. 读者释放不经过准入 latch。维护方枚举到读者后，读者可以在稳定读取锁快照期间正常结束。read/write 调度器只处理退休时的 residue-changed，遗漏了检查阶段的同类竞争，因此把合法释放作为异常退出。

## 实施边界

- 隐私引擎统一解析文件 URI、盘符、UNC 和 POSIX 路径，白名单比较前做对应路径语法的词法正规化；不查询文件系统，不把路径字符串当文件读取授权。需求文档的站内路由例外仍由需求能力决定，但使用同一套规范化分类。
- 补充环境变量与 JSON 赋值、Bearer/Basic 授权头、连接串用户信息和已列明的令牌前缀。继续使用既有凭证类别，没有增加放行策略或人工覆盖凭证的入口。
- 对所有可解码内容扫描。识别 CSI 格式序列并建立原文偏移映射；路径及标识按去格式视图检测，凭证同时检查原文，保留其他控制序列中可能存在的内容。未知控制和非 UTF-8 仍保留 opaque 人工审阅边界。原始 payload 字节不被清洗或重写。
- 回调复用已有 Markdown JSON 字面量渲染器，引用目标、摘要和分支；摘要明确标为不可信数据，传输无授权说明前置。inspect 仍只读，评审决定仍是独立的状态变更。
- 锁检查和退休期间的快照变化都返回“仍需等待”，在原有单调时钟期限内重新观察。未知所有者、异常文件和操作体异常不进入该重试分支；不提前进入写操作，不按时间抢锁。
- 并发测试把昂贵的真实初始化放入独立、有限时长的 setup，操作仍保留原有 20/25 秒时限和真实 fsync。没有通过延长行为时限或跳过持久化来消除失败。

## 保留限制

扫描器是已知形式的模式检测，不证明文本或二进制没有任何秘密。未列明的凭证形式、任意短口令、编码后的任意数据和 opaque 内容仍需正确选择与检查；报告里的任意 API 路由、产品 UUID 的策略本轮未放宽。

同用户恶意进程的文件权限隔离、可信调用者身份、窗口与 MCP 自动关联、Codex 聊天列表的项目归属回读均不由本次修复解决。回调引用和提示词边界也不等于操作系统或加密授权边界。

## 后续补审：披露判断、释放责任与身份保真

图谱只读审查转交 PF-02、CF-01、CB-01、PF-01 后，源码维护侧独立补回归并复现四类问题；图谱文件与历史探针保持只读。该批以 `1.1.0-rc.5` 生成候选，已安装的 rc.4 不被覆盖。

- **PF-02**：公共需求预览的 `privacyHit` 从已截断为 64 项的 blockers 反推，重复章节可挤掉已识别的隐私诊断，使摘要继续回显。文档分析现在单独保留披露事实，发布评估组合标题、正文及头部文本的隐私结果；只有诊断展示受数量上限约束。没有调换诊断次序来掩盖问题。回归覆盖两份文档正文、标题、测试摘要、搁置触发条件，以及缺确认/缺章节/大量重复的组合；无隐私命中的饱和诊断仍返回有用摘要。
- **CF-01**：`latched` 的 body 已取得读写许可，但短锁 release 抛错会跳过外层 await 赋值，清理变量保持 null。取得许可后立即登记外层释放责任；短锁结算仍可失败，业务体不会进入，已持有许可通过原来的精确删除释放。真实文件系统故障注入覆盖 shared/exclusive 注册阶段、exclusive 排空阶段，以及清理前许可被未知所有者替换的两个分支；未知替换字节保留，同进程后续读写准入不再被自身遗留许可挡住。
- **CB-01**：已准入的 Git 提交是 `{algorithm, value}`，`map(String)` 只产生 `[object Object]`。回调改为显式 `algorithm:value`，SHA-1/SHA-256 与中英文提示均覆盖。持久化结果身份及评审权威不变。
- **PF-01**：UUID 词法匹配在白名单检查之前排除了任意 `_`/`-` 前缀。现先识别完整 UUID 尾部，再只接受完整 token 起点上的已知前缀；未知前缀、嵌套已知前缀、空允许列表均不能自动放行。仍不匹配任意字母数字字符串内的 UUID 子串。
